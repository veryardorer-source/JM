# PRD Step 3 — 사용자 프로필 & 레시피 저장

## 개요
사용자 프로필을 관리하고, Step 2에서 마음에 든 레시피를 저장·조회·삭제한다.
별도 백엔드 없이 `localStorage`만으로 동작한다.

---

## 목표
- 사용자 프로필 설정(이름, 식단 선호, 알레르기) 저장
- 저장된 레시피 목록 조회 및 관리
- 저장 데이터가 앱 재시작 후에도 유지

---

## 기술 스택
| 항목 | 선택 |
|------|------|
| 프레임워크 | React 18 + Vite (동일 앱) |
| 데이터 저장 | localStorage |
| 상태관리 | React Context + useReducer |
| localStorage 키 | `fridge_profile`, `fridge_recipes` |

---

## 기능 요구사항

### 1. 사용자 프로필 설정
저장 항목:
| 필드 | 타입 | 설명 |
|------|------|------|
| `nickname` | string | 닉네임 (기본값: "나") |
| `dietType` | string | 식단 선호 (일반/채식/저칼로리) |
| `allergies` | string[] | 알레르기 재료 목록 |
| `servings` | number | 기본 인원 수 (1~4) |

- 프로필 설정 화면: 간단한 폼 (닉네임 입력, 드롭다운, 태그 입력)
- 저장 즉시 localStorage 반영
- Step 2 필터 기본값에 프로필 설정 자동 적용

### 2. 레시피 저장
저장되는 레시피 데이터 구조:
```json
{
  "id": "uuid-v4",
  "savedAt": "2026-05-14T10:30:00Z",
  "name": "당근 달걀볶음",
  "time": "15",
  "difficulty": "쉬움",
  "servings": 2,
  "ingredients_needed": ["달걀 2개", "당근 1/2개", "소금"],
  "steps": ["1. ...", "2. ..."],
  "tip": "...",
  "sourceIngredients": ["달걀", "당근", "양파"]
}
```
- 중복 저장 방지: 동일 `name`이 이미 있으면 "이미 저장된 레시피입니다" 토스트
- 최대 50개 저장 (초과 시 가장 오래된 항목 자동 삭제 후 저장)

### 3. 저장된 레시피 목록 (마이페이지)
- 저장 날짜 최신순 정렬
- 카드 형태로 표시 (이름, 조리 시간, 난이도)
- 카드 클릭 → 레시피 상세 모달
- 검색: 레시피 이름 또는 재료명으로 필터링
- 삭제: 각 카드에 [삭제] 버튼 (확인 없이 즉시 삭제)

### 4. 레시피 상세 모달
- Step 2 레시피 카드와 동일한 상세 내용 표시
- [삭제하기] 버튼
- [공유하기] 버튼 → 텍스트를 클립보드에 복사 (Web Share API fallback)

---

## 데이터 흐름
```
Step 2 [저장하기] 클릭
  → 중복 체크 (localStorage)
  → 중복 없으면 저장 + "저장되었습니다" 토스트
  → 중복 있으면 "이미 저장된 레시피입니다" 토스트

마이페이지 진입
  → localStorage에서 레시피 목록 로드
  → 카드 목록 렌더링
  → 검색 입력 → 실시간 필터링
  → 카드 클릭 → 상세 모달
  → 삭제 → localStorage 업데이트 → 목록 재렌더링
```

## 앱 전체 네비게이션 구조
```
앱 (App.jsx)
├── [Step 1] 이미지 업로드 & 재료 인식  ← 기본 진입점
├── [Step 2] 레시피 생성                ← Step 1 완료 후 이동
└── [마이페이지] 프로필 & 저장 레시피   ← 상단 네비 버튼
```

---

## 에러 처리
| 상황 | 처리 |
|------|------|
| localStorage 쓰기 실패 | "저장에 실패했습니다 (저장 공간 부족)" 토스트 |
| 저장 50개 초과 | 자동 삭제 후 저장 + "오래된 레시피 1개가 삭제되었습니다" 안내 |
| 클립보드 복사 실패 | 텍스트 영역으로 fallback 표시 |
